# LAN-Chat 匿名聊天室

LAN-Chat 是一个轻量级的局域网匿名聊天项目。服务端、网页界面和接口都集中在一个 `server.js` 文件中，不依赖数据库，也不需要部署单独的前端工程。

项目适合在家庭、宿舍、办公室、教室或临时活动现场使用。同一局域网内的用户通过浏览器访问服务地址，即可进入公共频道或发起一对一私聊。

项目还可以构建为 Windows 单文件程序。普通用户只需运行 `LAN-Chat.exe`，不需要安装 Node.js、npm 或其他运行环境。

## 功能介绍

### 聊天功能

- 提供 5 个公共聊天频道，默认名称为“频道1”“频道2”“频道3”“频道4”“频道5”。
- 点击左侧在线用户，可以切换到与该用户的一对一私人聊天。
- 私聊收到新消息时，用户列表会显示未读消息红点及数量。
- 有未读消息或最近私聊活动的用户会优先排列，避免消息提示被滚动区域遮住。
- 支持按用户名搜索在线用户。
- 支持选择表情，表情面板在输入栏上方自适应展开，点击面板外部会自动关闭。
- 支持在公共频道和一对一私聊中发送临时文件；默认单文件上限为 1 MB，管理员可实时调整；私聊接收方必须在线。
- 公共频道文件采用服务器磁盘中转；不超过 64 MB 的私聊文件优先尝试 WebRTC 点对点直传，连接失败、浏览器不支持或文件更大时自动回退服务器中转。
- 服务器中转采用 1 MB 分片、分片 SHA-256 校验和最终文件 SHA-256 校验；暂停会中断当前分片并在继续后重传，取消可在分片写入或最终校验期间立即生效，同时支持自动重试与 24 小时内重新选择同一文件续传。
- 公共频道文件仅允许当前位于对应频道的在线用户下载，私聊文件仅对双方开放。
- 消息与文件默认在发送 5 分钟后自动销毁，管理员可手动输入 1～1440 分钟内的整数并实时调整。
- 撤回文件消息时，对应临时文件会立即删除。
- 支持一键复制消息文本。
- 用户可在消息发出后的 3 分钟内撤回自己的消息。
- 私聊显示正在输入、已发送、已送达、已读、对方离线和文件接收状态。
- 使用浅色 iOS 26 液态玻璃视觉与纯 CSS 网格背景；主页面三列采用透明无框布局，大型管理员工具页使用轻量半透明渲染以降低模糊与折射开销。
- 桌面端和移动端消息气泡均按内容宽度自适应：短消息自动收缩，长消息最多占满头像旁的可用聊天宽度，四个角保持一致圆弧。
- 消息气泡底部平均排列复制按钮、剩余保留时间和撤回按钮。
- 复制、撤回、限流、文件传输和管理员操作使用页面顶部居中的悬浮提示，2 秒后自动消失。
- 聊天页面会根据浏览器窗口高度自动调整，消息区域独立滚动，输入框始终保留在页面底部。

### 用户与在线状态

- 首次进入时优先读取当前浏览器本地保存的用户名；没有本地记录时自动分配随机匿名用户名，并立即保存到浏览器。
- 用户修改名称后会同步更新浏览器本地存储，桌面端与移动端行为一致；清除浏览器站点数据后会重新随机分配。
- 用户头像根据当前昵称的首个字符自动生成，并从 50 组稳定渐变色中按昵称分配，便于区分不同用户。
- 用户名在当前在线会话中保持唯一。
- 左侧在线用户列表采用自适应高度，内容溢出后可独立滚动。
- 移动端通过顶部“用户”按钮打开在线用户抽屉，可搜索用户、查看私聊未读数量并进入一对一私聊。
- 移动端进入私聊后会自动收起用户抽屉，并可通过顶部选择器在私聊和公共频道之间切换。
- 聊天区域左上角以“频道名称（人数）”显示当前频道在线人数，右侧栏显示全站在线人数，用户列表显示各用户所在频道。
- 服务端通过定时轮询更新消息和在线状态。
- 全站最多允许 100 个在线会话。

### 使用限制与安全控制

- 非服务器本机地址每个 IP 最多建立 1 个在线会话。
- 服务器本机访问不受单 IP 会话数限制，便于在本机多开窗口测试。
- 每个会话在任意连续 5 秒内最多发送 2 条消息，文字与文件共用该限制。
- 单条消息最多 500 个字符。
- 公共频道和私聊均可发送文件，管理员可手动输入 1～20480 MB（20 GB）内的整数作为单文件大小上限，默认为 1 MB。
- 公共消息和私聊消息的保留时间可由管理员手动设置为 1～1440 分钟内的整数，默认为 5 分钟。
- 每个聊天记录集合最多保留 1000 条消息。
- 普通 JSON 请求体限制为 16 KB，文件使用独立的流式上传限制，具体上限以管理员当前设置为准。

### 管理员工具箱

管理员功能仅允许从运行服务的本机访问。

- 修改公共频道名称。
- 手动输入并实时调整消息与文件的销毁时间，范围为 1～1440 分钟。
- 手动输入并实时调整单文件大小上限，范围为 1～20480 MB（20 GB）。
- 两个限制输入框仅接受 `0–9`，字母、空格、标点和其他特殊字符会被自动过滤，服务端也会再次校验。
- 查看在线用户的 IP 地址、频道和在线状态。
- 封禁指定 IP，并立即断开该 IP 下的在线会话。
- 查看当前封禁列表和解除 IP 封禁。
- 频道名称、销毁时间、文件上限和 IP 封禁列表会写入本机配置文件，服务重启后继续生效。
- 禁止封禁服务器本机地址，避免管理员误操作。
- 管理员登录状态有效期为 1 小时，操作期间会自动续期。
- 管理员工具箱内部三列采用纯透明无卡片布局；管理员验证、工具箱和用户信息弹窗均可点击外部遮罩空白处关闭。

默认管理员密码为：

```text
666666
```

正式使用前建议通过 `ADMIN_PASSWORD` 环境变量修改密码。
管理员密码输入框具有清晰的原生闪烁光标，输入密码后可直接按 Enter 验证。

## 快速开始

### 方式一：直接运行 Windows EXE

下载，双击运行：

```text
LAN-Chat.exe
```

启动后控制台会显示访问地址，例如：

```text
LAN chat running on http://localhost:9000
LAN access: http://192.168.98.5:9000
```

- 服务启动成功后会自动使用系统默认浏览器打开 `http://localhost:9000`；如果修改了端口，则打开实际配置的本地地址。
- 同一局域网内的其他设备打开控制台显示的 `LAN access` 地址。
- 关闭程序的控制台窗口即可停止聊天服务。

普通使用者运行 EXE 时不需要安装 Node.js。

### 方式二：使用 Node.js 运行源码

安装 Node.js 后，在项目目录执行：

```powershell
node .\server.js
```

默认监听所有网络接口的 `9000` 端口。

## 发送临时文件

1. 进入需要发送文件的公共频道，或点击在线用户进入一对一私聊。
2. 点击输入框左侧的回形针按钮，选择需要发送的文件。
3. 文件发送成功后，频道内的在线用户或私聊双方可以在文件气泡中点击“下载”。

文件传输遵循以下规则：

- 文件按钮在公共频道和私聊中始终显示。
- 私聊只有对方在线时才能发送；如果上传期间对方离线，服务端会放弃消息并删除临时文件。
- 单个文件不能超过管理员当前设置的大小上限，空文件不能发送；默认上限为 1 MB。
- 公共文件消息只进入发送时所在的频道，切换到其他频道后无法下载该文件。
- 私聊文件消息只进入双方的私聊记录，其他用户无法通过下载接口获取文件。
- 下载地址包含随机令牌；服务端还会校验下载者当前所在频道，或是否为私聊参与者。
- 文件与消息使用管理员当前设置的保留时间，倒计时结束后无法继续下载；默认为 5 分钟。
- 发送者在 3 分钟内撤回文件消息时，文件会立即销毁。
- 文件发送计入“每 5 秒只能发送 2 条消息”的频率限制。
- 公共频道始终使用服务器中转；私聊文件不超过 64 MB 时优先使用 WebRTC 直传，失败后自动回退服务器。
- 服务器中转把文件拆为 1 MB 分片，每片及最终文件均进行 SHA-256 校验；界面支持进度、速度、剩余时间、暂停、继续和取消。暂停会立即中断正在发送的分片并在继续后从原偏移重传；取消会同步清理浏览器任务、服务端临时会话和点对点接收端的未完成数据。
- 上传中断后，在服务未重启、仍使用同一浏览器标签页且上传会话未超过 24 小时的前提下，重新选择同一文件会从已接收位置继续；刷新标签页后也可恢复。
- 服务端允许上传会话持续最多 12 小时，以支持大文件局域网传输；发送大文件前需确保服务器系统临时目录所在磁盘有足够可用空间。

## 配置项

项目支持通过环境变量修改端口、管理员密码，以及关闭启动时自动打开浏览器的行为。

PowerShell 示例：

```powershell
$env:LAN_CHAT_PORT = "8080"
$env:ADMIN_PASSWORD = "请设置一个强密码"
node .\server.js
```

运行 EXE 时也可以使用相同的环境变量：

```powershell
$env:LAN_CHAT_PORT = "8080"
$env:ADMIN_PASSWORD = "请设置一个强密码"
.\dist\LAN-Chat.exe
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LAN_CHAT_PORT` | `9000` | 服务监听端口，可用范围为 1～65535 |
| `ADMIN_PASSWORD` | `666666` | 服务器本机进入管理员工具箱时使用的密码 |
| `LAN_CHAT_NO_OPEN` | 未设置 | 设置为 `1`、`true`、`yes` 或 `on` 时，启动服务后不自动打开浏览器 |

## 构建 Windows 单文件程序

项目使用 Node.js Single Executable Application（SEA）机制构建 EXE，并默认使用 UPX 压缩 Node.js 运行时。构建机器需要 Node.js 26 或更高版本；最终使用者不需要 Node.js。

在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1
```

必须运行上面的 PowerShell 入口，不要直接执行 `node .\tools\build-exe.js`。控制台显示约 `94 MB` 时只是原始 Node SEA，继续等待出现 `Final size` 和 `Done`；此时 `dist\LAN-Chat.exe` 才是约 `23 MB` 的最终压缩版。

构建成功后生成：

```text
dist\LAN-Chat.exe
```

当前 Windows x64 构建实测由约 `93.8 MB` 压缩到约 `23.2 MB`，具体体积会随 Node.js 和 UPX 版本变化。

构建脚本会优先查找本机可用的 Node.js 26+。如果没有找到，会将便携版 Node.js 下载到项目的 `.build-tools` 目录。脚本还会下载官方 UPX 5.2.0，校验 SHA-256 后压缩最终 EXE，并对压缩结果执行完整性测试。未压缩的原始 SEA 只保存在 `build` 临时目录，只有压缩成功后才会更新 `dist` 中的最终文件。

如果需要未经 UPX 压缩的原始 SEA 文件，可以运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1 -SkipCompression
```

原始 SEA 会包含完整 Node.js 运行时，因此文件明显更大。构建完成后脚本会自动删除原始 SEA、临时页面、临时入口和 SEA 配置，只保留 `dist` 中的最终单文件程序。UPX 压缩版仍然是单文件程序，但未经数字签名的软件被压缩后可能更容易触发部分安全软件的启发式提示；公开分发时建议配置代码签名。

更详细的构建说明可查看 [EXE构建说明.md](./EXE构建说明.md)。

## 数据与生命周期

项目没有使用数据库，以下内容只保存在服务进程的内存中：

- 公共频道消息与私聊消息。
- 在线用户及会话状态。
- 私聊未读状态。
- 管理员登录令牌。
- 尚未完成的上传会话与 WebRTC 信令。

用户名会保存在访问设备当前浏览器的 `localStorage` 中，仅用于该浏览器下次进入时恢复，不会形成服务端账号或跨设备同步。浏览器禁用本地存储、使用部分隐私模式或清除站点数据时，页面仍可正常使用，但昵称可能重新分配。

通过服务器中转的频道文件和私聊文件不会完整保存在服务端内存中，而是分片写入系统临时目录。文件到期、被撤回或服务正常退出时会删除；磁盘兜底任务也会按照管理员当前设置的保留时间定期清理临时文件。WebRTC 直传文件只在通信双方的浏览器内处理，不写入服务器磁盘。

频道名称、销毁时间、文件大小上限和 IP 封禁列表会持久化到 `%LOCALAPPDATA%\LAN-Chat\config.json`；没有 `LOCALAPPDATA` 的系统会使用用户目录下的 `.lan-chat/config.json`。首次运行仍采用默认 5 分钟和 1 MB。关闭或重启服务会清空消息、在线状态、管理员令牌、未完成的上传会话和 WebRTC 信令，但不会重置上述管理员配置。

## 当前限制

- 公共频道和双方在线的一对一私聊均支持发送文件。
- 图片、语音和视频可以作为普通文件下载，但当前不提供聊天气泡内预览或播放。
- 没有用户账号、密码登录和历史消息持久化功能。
- 私聊以临时在线会话为基础，对方离线后不能继续发送。
- WebRTC 直传当前限制为不超过 64 MB 的在线私聊文件，较大文件和公共频道文件使用服务器分片中转。
- EXE 当前未进行数字签名，Windows 首次运行时可能显示安全提示。
- 当前构建产物面向 Windows x64；其他系统需要在对应平台单独构建或直接运行源码。

## 公网使用说明

当前版本更适合可信局域网或临时小范围使用，不建议未经额外防护直接暴露到公网。它目前使用普通 HTTP，并且没有数据库、正式账号系统、持久化审计、HTTPS、反向代理或分布式限流。

如果需要部署到公网，建议至少补充：

- 使用 Nginx、Caddy 或云平台反向代理并启用 HTTPS。
- 在服务器防火墙中只开放必要端口。
- 修改默认管理员密码，并使用高强度随机密码。
- 增加持久化封禁、访问日志和异常审计。
- 根据代理部署方式正确处理真实客户端 IP，避免所有访问被识别成代理服务器 IP。
- 增加验证码、全局限流、敏感内容治理和更严格的输入校验。
- 在正式开放前进行安全测试，并遵守部署所在地适用的法律法规。

## 防火墙提示

如果局域网内其他设备无法访问，请检查：

1. 设备是否连接到同一个局域网。
2. Windows 防火墙是否允许 `LAN-Chat.exe` 或 Node.js 通过专用网络。
3. 服务端和访问端之间是否存在 AP 隔离、访客网络隔离或路由器访问限制。
4. `9000` 端口是否已被其他程序占用；必要时可通过 `LAN_CHAT_PORT` 更换端口。

## 技术特点

- 原生 Node.js `http` 模块，无第三方运行时依赖。
- 原生 HTML、CSS 和 JavaScript，无前端框架依赖。
- 服务端与完整页面都内嵌在唯一的 `server.js`，源码运行只需要这一个文件。
- 页面响应支持预压缩 gzip，当前约 182 KB 的内嵌页面传输体积约为 43 KB。
- SEA 构建时使用临时无页面副本入口，成功后自动清理约 90 MB 的原始运行时和临时资源。
- 通过 HTTP 轮询同步消息和在线状态。
- 文件使用流式磁盘读写，不占用与文件大小等量的服务端内存。
- 支持构建为无需额外环境的 Windows 单文件程序。
