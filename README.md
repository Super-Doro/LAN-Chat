# VOID 匿名聊天室

VOID 是一个轻量级的局域网匿名聊天项目。服务端、网页界面和接口都集中在一个 `server.js` 文件中，不依赖数据库，也不需要部署单独的前端工程。

项目适合在家庭、宿舍、办公室、教室或临时活动现场使用。同一局域网内的用户通过浏览器访问服务地址，即可进入公共频道或发起一对一私聊。

项目还可以构建为 Windows 单文件程序。普通用户只需运行 `VOID-Chat.exe`，不需要安装 Node.js、npm 或其他运行环境。

## 功能介绍

### 聊天功能

- 提供 5 个公共聊天频道，默认名称为“唠嗑”“吐槽”“频道3”“频道4”“频道5”。
- 点击左侧在线用户，可以切换到与该用户的一对一私人聊天。
- 私聊收到新消息时，用户列表会显示未读消息红点及数量。
- 有未读消息或最近私聊活动的用户会优先排列，避免消息提示被滚动区域遮住。
- 支持按用户名搜索在线用户。
- 支持选择表情，表情面板从输入按钮右侧方向展开。
- 支持在一对一私聊中发送不超过 1 MB 的临时文件，接收方必须在线。
- 文件采用服务器磁盘流式中转，不会把完整文件加载到服务端内存。
- 文件下载仅对私聊双方开放，并在发送 5 分钟后自动销毁。
- 撤回文件消息时，对应临时文件会立即删除。
- 支持一键复制消息文本。
- 用户可在消息发出后的 3 分钟内撤回自己的消息。
- 消息气泡底部平均排列复制按钮、剩余保留时间和撤回按钮。
- 复制、撤回、限流、文件传输和管理员操作使用页面顶部居中的悬浮提示，2 秒后自动消失。
- 聊天页面会根据浏览器窗口高度自动调整，消息区域独立滚动，输入框始终保留在页面底部。

### 用户与在线状态

- 首次进入时自动分配匿名用户名和头像，也可以修改自己的名称与头像。
- 用户名在当前在线会话中保持唯一。
- 左侧在线用户列表采用自适应高度，内容溢出后可独立滚动。
- 移动端通过顶部“用户”按钮打开在线用户抽屉，可搜索用户、查看私聊未读数量并进入一对一私聊。
- 移动端进入私聊后会自动收起用户抽屉，并可通过顶部选择器在私聊和公共频道之间切换。
- 页面展示当前频道人数、全站在线人数以及用户所在频道。
- 服务端通过定时轮询更新消息和在线状态。
- 全站最多允许 100 个在线会话。

### 使用限制与安全控制

- 非服务器本机地址每个 IP 最多建立 1 个在线会话。
- 服务器本机访问不受单 IP 会话数限制，便于在本机多开窗口测试。
- 每个会话在任意连续 5 秒内最多发送 2 条消息，文字与文件共用该限制。
- 单条消息最多 500 个字符。
- 公共频道禁止发送文件；私聊文件最大为 1 MB。
- 公共消息和私聊消息仅在内存中保留 5 分钟。
- 每个聊天记录集合最多保留 1000 条消息。
- 普通 JSON 请求体限制为 16 KB，私聊文件使用独立的 1 MB 流式上传限制。

### 管理员工具箱

管理员功能仅允许从运行服务的本机访问。

- 修改公共频道名称。
- 查看在线用户的 IP 地址、频道和在线状态。
- 封禁指定 IP，并立即断开该 IP 下的在线会话。
- 查看当前封禁列表和解除 IP 封禁。
- 禁止封禁服务器本机地址，避免管理员误操作。
- 管理员登录状态有效期为 1 小时，操作期间会自动续期。

默认管理员密码为：

```text
666666
```

正式使用前建议通过 `ADMIN_PASSWORD` 环境变量修改密码。

## 快速开始

### 方式一：直接运行 Windows EXE

进入 `dist` 目录，双击运行：

```text
VOID-Chat.exe
```

启动后控制台会显示访问地址，例如：

```text
VOID chat running on http://localhost:9000
LAN access: http://192.168.1.10:9000
```

- 服务器本机使用浏览器打开 `http://localhost:9000`。
- 同一局域网内的其他设备打开控制台显示的 `LAN access` 地址。
- 关闭程序的控制台窗口即可停止聊天服务。

普通使用者运行 EXE 时不需要安装 Node.js。

### 方式二：使用 Node.js 运行源码

安装 Node.js 后，在项目目录执行：

```powershell
node .\server.js
```

默认监听所有网络接口的 `9000` 端口。

## 发送私聊文件

1. 在左侧在线用户列表中点击一名用户，进入一对一私聊。
2. 确认聊天顶部显示对方“在线”。
3. 点击输入框左侧的回形针按钮，选择需要发送的文件。
4. 文件发送成功后，双方都可以在文件气泡中点击“下载”。

文件传输遵循以下规则：

- 文件按钮只在一对一私聊中显示，公共频道不显示文件入口，也不能上传文件。
- 只有对方在线时才能发送；如果上传期间对方离线，服务端会放弃消息并删除临时文件。
- 单个文件不能超过 1 MB，空文件不能发送。
- 文件消息只会进入双方的私聊记录，其他用户无法通过下载接口获取文件。
- 下载地址包含随机令牌，同时还会校验下载者是否为该私聊的参与者。
- 文件与消息一样保留 5 分钟，倒计时结束后无法继续下载。
- 发送者在 3 分钟内撤回文件消息时，文件会立即销毁。
- 文件发送计入“每 5 秒只能发送 2 条消息”的频率限制。

## 配置项

项目支持通过环境变量修改端口和管理员密码。

PowerShell 示例：

```powershell
$env:VOID_CHAT_PORT = "8080"
$env:ADMIN_PASSWORD = "请设置一个强密码"
node .\server.js
```

运行 EXE 时也可以使用相同的环境变量：

```powershell
$env:VOID_CHAT_PORT = "8080"
$env:ADMIN_PASSWORD = "请设置一个强密码"
.\dist\VOID-Chat.exe
```

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VOID_CHAT_PORT` | `9000` | 服务监听端口，可用范围为 1～65535 |
| `ADMIN_PASSWORD` | `666666` | 服务器本机进入管理员工具箱时使用的密码 |

## 构建 Windows 单文件程序

项目使用 Node.js Single Executable Application（SEA）机制构建 EXE。构建机器需要 Node.js 26 或更高版本；最终使用者不需要 Node.js。

在项目目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1
```

构建成功后生成：

```text
dist\VOID-Chat.exe
```

构建脚本会优先查找本机可用的 Node.js 26+。如果没有找到，会将便携版 Node.js 下载到项目的 `.build-tools` 目录后再进行构建。

更详细的构建说明可查看 [EXE构建说明.md](./EXE构建说明.md)。

## 数据与生命周期

项目没有使用数据库，以下内容只保存在服务进程的内存中：

- 公共频道消息与私聊消息。
- 在线用户及会话状态。
- 私聊未读状态。
- IP 封禁列表。
- 管理员登录令牌。

私聊文件不保存在内存中，而是流式写入系统临时目录。文件到期、被撤回或服务正常退出时会删除；磁盘兜底任务也会定期清理超过 5 分钟的临时文件。

关闭或重启服务后，内存数据会全部清空。消息和文件在服务持续运行期间只保留 5 分钟。

## 当前限制

- 文件只能在双方在线的一对一私聊中发送，公共频道不支持文件。
- 图片、语音和视频可以作为普通文件下载，但当前不提供聊天气泡内预览或播放。
- 没有用户账号、密码登录和历史消息持久化功能。
- 私聊以临时在线会话为基础，对方离线后不能继续发送。
- IP 封禁记录在程序重启后会清空。
- EXE 当前未进行数字签名，Windows 首次运行时可能显示安全提示。
- 当前构建产物面向 Windows x64；其他系统需要在对应平台单独构建或直接运行源码。

## 公网使用说明

当前版本更适合可信局域网或临时小范围使用，不建议未经额外防护直接暴露到公网。它目前使用普通 HTTP，并且没有数据库、正式账号系统、持久化审计、HTTPS、反向代理或分布式限流。

如果需要部署到公网，建议至少补充：

- 使用 Nginx、Caddy 或云平台反向代理并启用 HTTPS。
- 在服务器防火墙中只开放必要端口。
- 修改默认管理员密码，并使用高强度随机密码。
- 增加持久化封禁、访问日志和异常审计。
- 根据代理部署方式正确处理真实客户端 IP，避免所有访问被识别成代理服务器 IP。
- 增加验证码、全局限流、敏感内容治理和更严格的输入校验。
- 在正式开放前进行安全测试，并遵守部署所在地适用的法律法规。

## 防火墙提示

如果局域网内其他设备无法访问，请检查：

1. 设备是否连接到同一个局域网。
2. Windows 防火墙是否允许 `VOID-Chat.exe` 或 Node.js 通过专用网络。
3. 服务端和访问端之间是否存在 AP 隔离、访客网络隔离或路由器访问限制。
4. `9000` 端口是否已被其他程序占用；必要时可通过 `VOID_CHAT_PORT` 更换端口。

## 技术特点

- 原生 Node.js `http` 模块，无第三方运行时依赖。
- 原生 HTML、CSS 和 JavaScript，无前端框架依赖。
- 服务端与页面资源合并，部署文件少。
- 通过 HTTP 轮询同步消息和在线状态。
- 文件使用流式磁盘读写，不占用与文件大小等量的服务端内存。
- 支持构建为无需额外环境的 Windows 单文件程序。
